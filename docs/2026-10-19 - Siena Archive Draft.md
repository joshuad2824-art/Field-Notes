Based on verified main `0da2a4a`. Production remained Netlify `6ad4035c5e80357abb07cdde` from `f84feee` when work began. The older local main checkout and its untracked duplicate source files were preserved untouched. This draft is in a separate worktree and branch.

## Scope

One shared read-only renderer covers Today, From Siena, St. John and other notebook desks, Archive and reminder detail text. It reuses the existing safe React Markdown renderer, with bold section headings, italic emphasis, spacing, readable lists and restrained highlights. Stored message text is unchanged. Today's Siena container is now a semantic section with links on its heading/title, allowing safe links inside formatted messages without nested anchors.

Archive is a searchable view of original Siena item rows, not notebook pages or moved/deleted copies. Completed reminders appear there immediately and can be reopened. Other Siena messages stay active for at least 72 elapsed hours. `requiresAction: false` explicitly identifies informational messages. Unknown legacy messages remain active until the user resolves them. Seen status never resolves an item. Resolving a recent message still keeps it through the minimum age. Restoring a message pins it active until explicitly released; reopening a resolved action clears resolution. Stale disposition writes are refused using the existing updated timestamp.

Active messages replace the Earlier notes/Completed reminders expanders in From Siena and notebook desks. St. John retains all active briefs, with an Archive link for its notebook. Existing notebook writing is untouched. Archive is available from From Siena, the app's back-room menu and reminder history. Time-based membership refreshes every minute while those screens remain open.

New nullable `requires_action`, `resolved_at`, `retained_at`, `state_at` metadata is additive. The separate `state_at` clock makes completion, restore, resolve, reopen, release and filing reversible across devices while seen state remains monotonic. The sync reconciler rechecks state inside the write transaction and before pushing so an in-flight pull cannot erase a newer tap. Sync mapping, equality, backup validation/import and the hosted publisher preserve it. Publication can describe action status but cannot set resolution/restoration; the migration retains vault access rules and tightens linked-assistant insertion accordingly. No migration or function deployment has been performed.
